# 挑战赛赔率口径差异（2026-10-21 实测）

> 起因：核对服务端 `msgId=11`（账号私有「我已预测」真值）与本地
> `challenge_state.json` 时，发现 5 条本地没记的记录，顺带查出更深的问题。

## 一、账目缺口（A）

服务端 33 条 vs 本地 state 28 条，差 5 条：

| 比赛 | 服务端 market | 方向@赔率 |
|---|---|---|
| 比利亚雷亚尔 vs 那不勒斯 | 4 | 主胜@2.04 |
| 马德里竞技 vs 曼彻斯特联 | 4 | 主胜@1.75 |
| 朗斯 vs 葡萄牙体育 | 4 | 主胜@2.27 |
| 阿森纳 vs 里尔 | 5 | 客胜@2.04 |
| 莱比锡红牛 vs 埃因霍温 | 5 | 客胜@2.03 |

### market 4/5 的语义已钉死：是让球

**更正**：本文初稿写「口径对不上任何一种已知市场」——那是我只拿赔率去
反查、没去站点上翻实盘。后来打开 `/prediction/mine` 的「已预测」标签，
站点自己把玩法写得很清楚：

```
阿森纳 vs 里尔      让负(-2)@2.04   ← market=5
莱比锡红牛 vs 埃因霍温  让负(-1)@2.03   ← market=5
```

**结论：market 4 = 让球主队方向，market 5 = 让球客队方向。**
（market 1 = 胜平负，market 2 = 让球的老编码。）

这也解释了为什么赔率对不上 1x2：它们本来就不是 1x2。阿森纳那场
1x2 是 1.10/6.70/14.00，但「让负(-2)」= 让两球后客队赢，赔率 2.04，
两者是不同的赌法。

### 仍然不补记，但理由变了

不是「口径不明」，而是**本地 state 的 schema 装不下**：

| | 本地 `records` 字段 | 让球注需要 |
|---|---|---|
| `market` | 固定写 `"1x2"` | 应为 `"handicap"` |
| `line` | 恒为 `null` | 需要让球线（-1 / -2 / +0.5） |
| `pick` | `"主胜@2.04"` | 需要 `"让负(-2)@2.04"` |

`challenge_hourly.py:182` 写记录时硬编码了 `"market": "1x2"` 和
`"line": None`。**这 5 条让球注被记成了 1x2**，会让复盘把让球命中率
算进 1x2 池子里。这比「漏记」更麻烦——是**错记**。

所以：这 5 条不补（补了也是按错误 schema 补），改为在
`docs/` 里存站点原文（见下），并把「让球注 schema」列为待修项。

（顺带：这 5 条正是 `challenge_state.json` 里 `records_gap_note` 记的
「CI 化后 state 从未成功回写」的历史缺口。现在去重已改走服务端真值
`api.my_predictions`，**不会再新增缺口**。）

## 二、赔率口径差异（B）—— 这个影响更大

### 现象

拿 18 条可对照的 1x2 记录，比「本地记的赔率」与「服务端实际成交赔率」：

```
赔率差(成交 − 本地): 均值 +0.186  中位 +0.190  区间 [0.00, +0.39]
比值(成交 / 本地):   均值 1.0993  中位 1.1058
方向：成交更高 17 条，相同 1 条，更低 0 条
```

**本地赔率系统性低估约 10%，18 条里 17 条都是低估。**

### 根因：两个不同来源的赔率

- `predictions.json` 的 `home_odds/draw_odds/away_odds` 来自**体彩官方**
  （`engine/sources/sporttery.py` → `fixture.home_odds`）
- 挑战赛成交用的是 **NJStats 站点自己的赔率**（`msgId=11` 的 f2.f3）

同场对照（2026-10-21）：

| 比赛 | 体彩(主/平/客) | 站点(主/平/客) |
|---|---|---|
| 东京FC vs 柏太阳神 | 2.09/3.45/2.78 | 2.10/3.50/3.30 |
| 大宫松鼠 vs 富山胜利 | 2.15/3.67/2.55 | 2.20/3.70/2.88 |
| 布鲁日 vs 朗斯 | 1.86/3.70/3.12 | 2.00/4.10/3.20 |

站点赔率普遍更高（客胜尤其明显：2.78→3.30）。**这不是数据错误，
是挑战赛的赔率设定**（用更高赔率吸引参与）。

### 影响：EV 被系统性低估 9.7 个百分点

用两种赔率分别算 EV = P × odds − 1（P 取 `final_prob`）：

```
用体彩赔率：EV 均值 −6.9%
用站点赔率：EV 均值 +2.8%
17 注里有 12 注从负 EV 翻成正 EV
```

### 但今天（10-21）的零合格是真的

13 场里 `edge≥1.5pp` 的 0 场，`EV>0` 的也 0 场——即使换成站点赔率
也全是负 EV（−7.7% ~ −11.6%）。所以**今天不投是对的**。

### 该不该改？

`challenge_hourly.py:144` 用 `predictions.json` 的赔率算 edge，
而实际成交用站点赔率。**筛选用的是 A 套价、成交用 B 套价**，这在
逻辑上不自洽。

但改它属于**策略层改动**，按 AGENTS.md 必须走配对回放裁决，
且要考虑：

1. 站点赔率只在**提交那一刻**可见，历史无法回溯（`msgId=11` 只给
   已预测的，`msgId=1` 全板给的是当前价）。**没有历史 → 无法回测**。
2. 用高赔率算出来的 EV 更高，会放进更多注。但 E3/E6 已证明
   **模型自称的 edge 与实际兑现几乎不相关**——放宽筛选未必赚更多。
3. 挑战赛的积分规则是「赔率越高、命中得分倍数越高」，所以高赔率
   对**积分**有利，但对**胜率**不利。这是两个不同目标。

**结论：先记录，不改。** 要动的话，前置条件是把站点赔率每天快照下来
（类似社区倾向那样攒样本），攒够后做配对回放。这次不做。

## 四、待修：让球注被错记成 1x2

`challenge_hourly.py:182` 写记录时：
```python
st["records"].append({"match": ..., "pick": ...,
                      "market": "1x2",   # ← 硬编码
                      "line": None,      # ← 让球线丢失
                      ...})
```

而 `challenge_hourly.py` 本身**只投 1x2**（`api.submit(jwt, sid, 1, dir+1)`，
第二个参数 mkt=1）。所以：

- **CI/本机自动投的注，`market="1x2"` 是对的**
- **那 5 条让球注是人工/旧脚本投的**（ZCode 时代的让球分支），
  写进 state 时被套用了 1x2 的 schema

结论：自动链路没有错记问题，**是历史人工注的 schema 遗留**。
修的话要做两件事（都不急）：
1. `records` 增加 `play`（1x2/handicap）与 `line` 字段，写入时按实际填报
2. 复盘脚本按 `play` 分池统计，别把让球混进 1x2

# 模型权重归零评估（2026-10-28）

> 结论先行：**不建议现在归零**。在 810 场 v2 洁净样本上，`model_weight 0.05 → 0`
> 对 Brier 是 −0.0003 的微改善（95%CI 跨 0，t=0.73），但 argmax 命中率反而
> 降 0.3pp（57.0%→56.7%）。没有一项指标显著占优；而归零要付 chain/测量口径的成本。
> 生产权重**未改**，`fusion_weights.json` 仍是 `0.05 / 0.75 / 0.20`。

## 为什么还要再看一次

`docs/EXPERIMENTS.md` 的六条证据（E0–E5）已经说明：**纯模型**比去水市场差
（7 万场 ΔBrier=+0.02018，t=34.74，21/21 联赛 FDR 显著）。但那只回答了
"模型单独用行不行"，没有回答"模型占 5% 的融合槽位值不值"。

两者不是一回事：5% 的权重会把模型的负贡献稀释成 ~0.001 Brier 量级，
正好落在 800 场账本的检测下限附近。所以需要一次**直接的、单变量的**配对回放。

## 方法

扩展 `scripts/ablation_replay.py`，新增 `model_weight_sweep` 段：

| 设计点 | 取值 |
|---|---|
| 数据 | `review_ledger.jsonl` 的 v2 洁净样本 **810 场**（排除 426 行 legacy、20 场污染） |
| 回放函数 | 生产同款 `fuse_probabilities`，后处理开关取 `config/prediction.json` 的**生产值**（`same_odds_bias=true`，其余 false） |
| 单变量 | 模型槽设为 w，市场/DJYY 按 **0.75:0.20 原比例**分掉 1−w（不改变内部配比） |
| 对照 | 现行 champion（0.05/0.75/0.20），逐场配对 Brier |
| 切分 | 按日期前 60% 定参 / 后 40% 验证（486 / 324） |
| 统计 | 配对均值、SE、t、95%CI；另报 argmax 方向变化率 |
| 有效权重 | 有 DJYY 的场次 5.00%，无 DJYY 的场次 6.25%（DJYY 覆盖 21.4%） |

命令：`python scripts/ablation_replay.py --out data/state/ablation_report.json`
报告 JSON 的 `model_weight_sweep` 段包含全部逐臂数字。

### 方向只变 7 场（0.9%）

7 场里：现行 5% 的 argmax 命中 **3 场**，归零命中 **0 场**，其余 4 场两边都没中
（多数实际结果是平局）。样本太小不能作结论，但它说明"归零"不是单向改善，
而是在 Brier 与 argmax 之间做了一次几乎等价的置换。

## 解释

1. **"模型没有 edge" 与 "归零能改善系统" 是两件事。**
   7 万场说明模型单独用差 0.02 Brier；按线性外推，5% 权重应带来 ~0.001 的损失。
   但融合是归一化 + DJYY 门槛 + 后处理的非线性组合，实测 Δ=−0.0003±0.0005，
   与 0 不可区分，也**没有复现**线性外推的 +0.001。
2. **检测力不够。** 以当前配对差的标准差（≈0.0137）计算，要在 t=2 检出 0.0003
   的差异需要 **≈8,300 场 v2 样本**；现在 810 场，按 ~400 场/月累积，还需约 19 个月。
   换句话说：**一年内靠账本都无法裁决这件事。**
3. **归零的真实成本不在性能，在 chain 语义。** 新样本的 `final_prob` 会由
   "模型 5% 融合"变成"市场主导"，但 `chain` 仍是 v2：
   - `upgrade_tracker` 的 Q1 是 v2 对 legacy 的 Brier 比较。市场化样本的 Brier
     本来就更接近市场基准（0.5652 vs 融合 0.5580），混进来会把 Q1 抬高，
     **制造出"升级生效"的假改善** —— 正是本项目最忌讳的那类误读。
   - 要么把 chain 升到 v3（calibration/LGBM/tracker 的 810 场历史全部作废，
     重走 10-11 那次归零的老路），要么给账本加 `gen` 字段并改所有消费者
     （calibration_auto / lgbm_shadow / upgrade_tracker）。两者都不是一行改动。
4. **0.001 Brier 不是瓶颈。** 竞彩抽水中位 12.1%，决策层门槛是 1.5–2pp 的 EV。
   在一个 0.001 量级的差异上做 chain 手术，收益与风险不匹配。

## 建议

**维持 0.05，不动生产。** 理由：无显著收益、命中率略降、chain 成本真实、
且该量级远小于抽水与决策噪声。

保留模型槽位的另一个作用是**研究探针**：`model_raw` 继续逐场入库，
`ablation_replay` 每月可以零成本重算"归零反事实"，不需要改生产就能持续积累证据。

### 如果你仍决定归零（回退路径已备好）

改动只有一行（`data/state/fusion_weights.json`）：

```json
"champion": {"model": 0.0, "market": 0.75, "djyy": 0.2}
```

回退：把 `model` 改回 `0.05`。周度优化器不会把它翻回去——晋升要求
`improvement ≥ max(0.005, 1.96×SE)`，而 0↔0.05 的差异只有 0.0003 量级。

但**必须同时选一个 chain 处理方案**，否则 Q1 会被污染：

| 方案 | 动作 | 代价 |
|---|---|---|
| A. 加 `gen` 字段 | `post_match` 写入生成器标记；`upgrade_tracker` 只比较同代样本；calibration/LGBM 显式声明用哪代 | 改 2–3 个消费者，约 50 行；无样本损失 |
| B. chain 升 v3 | 新样本 chain=v3；消费者白名单加 v3 | 810 场 v2 对自动学习失效（当前三者都关着，短期无感；但 Q1/LGBM 需重新攒） |

我的建议是 A；如果只想要"最小可回退"，那就维持现状。

- 810 场、观察性分析（首次扫描发生在登记之前，属于流程瑕疵；E11 只登记
  确认性判据，不追认本次为预注册实验）。
- 回放不含 `lgbm_blend` / `isotonic` / `temperature` / `freshness`——四者在生产
  配置里都是关闭的，残差（存储 final − 回放全开）仅 −0.0004。
- 只看了概率指标，没有重放 EV 闸门与出票 ROI；方向变化仅 7 场，对出票的
  影响大概率同样在噪声内。
- 数据只覆盖 2026-08-29 起的 v2 链；legacy 426 场不参与（重放会带系统性偏差）。

### 测试体系结构性建议

1. **属性测试（hypothesis）**优先补纯函数层：fusion/kelly/devig/paired_test/time_decay 把手写 `random.Random(seed)` 换成 hypothesis 策略，自动覆盖边界形状（0、负、极大、非归一化）并最小化反例。现在 2000 个固定种子场景只覆盖"和=1"一个形状族。
2. **黄金样本回归**：test_fusion.py 的 `_reference_inline` 是已有正确范式，推广到：① 生产 post_fusion 配置组合快照；② main.py 候选循环输出快照；③ 脱敏真实账本的 ablation_replay 输出快照。
3. **变异测试（mutmut/cosmic-ray）**：大量测试是"源码文本断言"（regex 锁 main.py 文本），对行为变异可能零杀灭。对 fuse_probabilities/kelly/devig/paired_test 跑变异，把杀灭率纳入 CI 指标。
4. **行为级脚本测试模式推广**：test_ci_workflow_resilience.py（真 git 仓库跑真脚本）是标杆。ablation_replay/edge_calibration 重构为"根目录可注入 + main(argv) 可调用"，用 tmp 数据目录做行为测试——同时解决盲区 #3/#10。
5. **不变量守护测试独立成文件**：账本 append-only、SHA-256 链、plan_lock 后不可改、概率和=1、权重和=1、限额上界——各一个独立测试文件，CI 全量跑。
6. **补覆盖率度量**：CI 现在只有 pytest + ruff F，无覆盖率数字。加 pytest-cov，对 fusion/kelly/integrity/calibration_auto 设行覆盖门槛（建议 ≥80%）并看趋势。
7. **脏数据模糊测试**：对 sources 解析层建小型 fuzz 语料库（截断 JSON、GBK 乱码、字段缺失、类型错位）——历史事故主因是"静默失败"，fuzz 是最 cheap 的对抗手段。
8. **测试数据构造 helpers 沉淀到 conftest**：多个测试各自手写 `_write_daily/_mk_records/_norm3`，沉淀为 fixtures（make_daily_dir、make_ledger、rand_probs），降低补用例成本。
